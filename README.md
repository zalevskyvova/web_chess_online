# ♟️ Web Chess Online — Веб-орієнтована система для гри в шахи в реальному часі

Веб-додаток для онлайн-гри в шахи з підтримкою локального мультиплеєра через кімнати та одиночної гри проти інтелектуального бота на базі FastAPI та сучасних фронтенд-технологій.

Проєкт виконано з акцентом на архітектурну чистоту, високу продуктивність (завдяки асинхронності FastAPI) та преміальний адаптивний інтерфейс користувача.

---

## 🏛️ Архітектура системи та принцип роботи

Система побудована за архітектурним шаблоном **Client-Server (Клієнт-Сервер)** із чітким розділенням зон відповідальності (Separation of Concerns):

```mermaid
graph TD
    subgraph Frontend [Клієнтська частина (Браузер)]
        UI[Адаптивний HTML5/CSS3 Інтерфейс] <--> JS[Клієнтський контролер game.js]
        JS -- Рендеринг зображень фігур --> Board[Шахова дошка / CSS Grid]
    end

    subgraph Backend [Серверна частина (FastAPI)]
        API[FastAPI Router / Ендпоінти] <--> Logic[Шаховий двигун chess_logic.py]
        Logic <--> PyChess[Бібліотека python-chess]
        CleanTask[Фоновий процес очищення кімнат] -.-> Logic
    end

    subgraph External [Зовнішні сервіси]
        Lichess[Lichess Cloud Eval API]
    end

    JS -- HTTP POST / JSON API --> API
    Logic -- REST HTTP Requests --> Lichess
```

### Компоненти взаємодії:
1. **Frontend (Клієнт)**:
   * **HTML5 / CSS3 (Vanilla)**: Реалізує графічну оболонку з використанням HSL-палітри кольорів, CSS Grid для дошки та плавних CSS-переходів (Micro-animations).
   * **Vanilla JavaScript (`game.js`)**: Відповідає за парсинг нотації FEN (Forsyth-Edwards Notation), клієнтську валідацію, обробку подій кліків, роботу з таймерами гри та періодичне опитування (polling) стану сервера.
2. **Backend (Сервер на FastAPI)**:
   * **`main.py`**: Точка входу додатка. Надає асинхронні HTTP API ендпоінти, здійснює менеджмент ігрових кімнат в оперативній пам'яті (In-Memory State Management) та запускає фонові завдання (background tasks) для очищення неактивних кімнат.
   * **`chess_logic.py`**: Забезпечує інтеграцію з бібліотекою `python-chess` для суворої валідації ходів на стороні сервера, виявлення шаху/мату/пату та взаємодії із зовнішнім штучним інтелектом.
3. **Зовнішній AI Сервіс**:
   * Для розрахунку оптимальних ходів бота використовується **Lichess Cloud Evaluation API**, що забезпечує професійну якість гри без навантаження на локальний сервер.

## 🌟 Ключовий функціонал

1. **Режим гри проти бота (Singleplayer)**:
   * 4 рівні складності: `easy`, `medium`, `hard` та `unbeatable`.
   * Динамічний вибір кольору фігур (гра за білих, чорних або випадковий вибір).
2. **Мультиплеєр через кімнати (Multiplayer)**:
   * Створення унікальних кімнат з автоматичним генератором 6-значних буквено-цифрових кодів.
   * Підключення другого гравця за кодом кімнати.
3. **Система контролю часу (Time Control)**:
   * Підтримка 9 пресетів часу (від бліцу `1+0` до класики `30+0` та гри без ліміту часу `unlim`).
   * Клієнт-серверна синхронізація таймерів у реальному часі.
4. **Сучасний ігровий інтерфейс (UI/UX)**:
   * **Сучасна колірна схема**: Контрастна сіра палітра клітинок дошки (світлі клітинки — `#b8bcbe`, темні — `#4e5254`), що мінімізує втому очей.
   * **Кастомні піксельні фігури**: Інтегровано унікальний набір графічних асетів високої якості (оптимізовані PNG-файли).
   * **Динамічний контраст координат**: Символи вертикалей (`a-h`) та горизонталей (`1-8`) адаптують свій колір залежно від фону клітинки для максимальної читаності.
   * **Тактильний відгук**: Плавне збільшення фігури при наведенні курсору (`transform: scale(1.08)`).
5. **Інформаційна панель**:
   * Інтерактивне ведення історії ходів у стандартній шаховій нотації SAN (Standard Algebraic Notation).
   * Можливість дострокового завершення гри: **Здача (Resign)** або **Нічия за згодою (Draw)**.

## 🛠️ Технічний стек

| Компонент | Технологія | Роль у проєкті |
|-----------|------------|----------------|
| **Backend Framework** | **FastAPI (Python 3.12)** | Швидкий, асинхронний веб-фреймворк для розробки API. |
| **Chess Engine** | **python-chess** | Бібліотека для повної валідації ходів, генерації дозволених ходів та роботи з FEN. |

| **Frontend Core** | **HTML5 (Semantic), Vanilla JS** | Структура сторінок та клієнтська логіка без додаткових великих фреймворків. |
| **Styling** | **CSS3 (Custom HSL System)** | Преміальний інтерфейс з ефектом Glassmorphism, анімаціями та адаптивною сіткою Grid. |

## 🔬 Глибокий аналіз реалізації ключових модулів

### 1. Серверна логіка та інтеграція з AI (`chess_logic.py`)
Сервер оперує об'єктом `chess.Board` з бібліотеки `python-chess`. Це виключає будь-яку можливість читерства або виконання некоректних ходів на клієнті. При отриманні запиту на хід сервер:
1. Перевіряє, чи хід є легальним (`move in board.legal_moves`).
2. Оновлює стан дошки.
3. Якщо гра ведеться проти бота, сервер формує асинхронний запит до **Lichess Cloud Evaluation API**, передаючи поточну позицію у форматі FEN. Бот повертає найкращий прорахований хід (best move), який сервер застосовує до дошки та повертає клієнту.

### 2. Клієнтська логіка рендерингу (`static/js/game.js`)
Рендеринг шахової дошки виконується динамічно на основі рядка FEN. Рядок парситься функцією `parseFEN()`, яка створює карту розташування фігур на клітинках.
Клітинки генеруються за допомогою CSS Grid. Для кожної фігури створюється елемент `<img>` із посиланням на відповідний графічний асет у папці `static/images/pieces/`.

### 3. Автоматичний менеджмент пам'яті (Garbage Collection)
Щоб запобігти витоку пам'яті через накопичення неактивних ігрових кімнат, у файлі `main.py` реалізовано періодичну фонову задачу (FastAPI Background Task). Кожні 5 хвилин система сканує активні кімнати та видаляє ті, в яких не було зроблено жодного ходу протягом останніх 5 хвилин.

## 🚀 Інструкція з розгортання та локального запуску

Проєкт повністю готовий до демонстрації та запускається у кілька простих кроків:

### 1. Клонування репозиторію
```bash
git clone -b zalevskyvova_branch https://github.com/zalevskyvova/web_chess_online.git
cd web_chess_online
```

### 2. Налаштування віртуального середовища (Virtual Environment)
Для ізоляції залежностей рекомендується використовувати стандартний модуль `venv`:

**Для Windows:**
```bash
python -m venv venv
venv\Scripts\activate
```

**Для Linux / macOS:**
```bash
python3 -m venv venv
source venv/bin/activate
```

### 3. Встановлення залежностей
Встановіть усі необхідні Python-модулі однією командою:
```bash
pip install -r requirements.txt
```

### 4. Запуск веб-сервера
Запустіть асинхронний сервер Uvicorn:
```bash
uvicorn main:app --reload
```

Сервер успішно запуститься за адресою: **[http://localhost:8000](http://localhost:8000)**. Відкрийте це посилання у будь-якому сучасному браузері.

## 📡 Специфікація API Ендпоінтів

Для комунікації клієнта з сервером розроблено RESTful JSON API:

* **`POST /create-room`** — Створення нової гри. Приймає JSON із параметрами `time_control`, `difficulty`, `against`. Повертає згенерований `room_id` та колір гравця (`color`).
* **`POST /join-room`** — Приєднання до гри. Приймає `room_id`. Повертає статус успішності приєднання.
* **`POST /board`** — Отримання поточного стану гри. Приймає `room_id`. Повертає рядок `current_FEN`, час таймерів обох гравців, чергу ходу та поточний статус матчу (`playing`, `checkmate`, `draw` тощо).
* **`POST /move`** — Спроба зробити хід. Приймає координати ходу в UCI-форматі (наприклад, `e2e4`) та `room_id`. Повертає оновлений стан дошки та хід-відповідь бота (якщо увімкнено одиночний режим).
* **`POST /resign`** — Передчасна здача партії гравцем.
* **`POST /draw`** — Запит або погодження на нічию.

## 🎓 Висновки для захисту проєкту

Дана система демонструє практичне застосування сучасного веб-стеку для побудови інтерактивних додатків реального часу:
1. **Висока продуктивність**: Завдяки асинхронній природі **FastAPI (ASGI)**, додаток здатний одночасно обробляти сотні ігрових сесій з мінімальним споживанням системних ресурсів.
2. **Безпечність ігрового процесу**: Вся критична логіка (валідація ходів, облік часу, визначення переможця) винесена на **Backend**. Клієнт виконує виключно функцію відображення (рендерингу) та зчитування дій користувача, що унеможливлює злам гри на стороні браузера.
3. **Сучасний UX**: Інтерфейс адаптований під будь-які екрани (responsive design) та пропонує плавні переходи й унікальну колірну гаму, створюючи приємне візуальне враження.
